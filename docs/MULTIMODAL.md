# Multimodal (Vision) Support

This document describes how to use vLLM Runner with multimodal models that process both text and images.

## Overview

vLLM Runner supports OpenAI-compatible vision API formats for processing text + image data. The framework includes:

- **MultimodalDataLoader**: Base class for building custom multimodal loaders
- **MultimodalJSONLDataLoader**: Load vision data from JSONL files
- **MultimodalJSONDataLoader**: Load vision data from JSON array files
- **OpenAIAdapter**: Fully compatible with OpenAI vision API format

## Supported Loaders

### 1. MultimodalJSONLDataLoader

Loads multimodal data from JSONL files (one JSON object per line).

#### JSONL Format

```jsonl
{"id": "1", "prompt": "Describe this image", "image": "path/to/image.jpg"}
{"id": "2", "prompt": "What's in this photo?", "image": "photos/sample.png"}
{"id": "3", "prompt": "Compare these", "images": ["img1.jpg", "img2.png"]}
```

#### Configuration

```yaml
loader:
  class: MultimodalJSONLDataLoader
  params:
    file_path: data/prompts.jsonl
    prompt_field: prompt          # Field containing text prompt
    id_field: id                  # Field containing ID
    image_field: image            # Single image field
    images_field: images          # Multiple images field
    image_base_dir: data/images   # Base dir for relative paths
    encode_images: true           # Auto-encode to base64
```

#### Image Field Precedence

1. If `image` field exists → use it (single image)
2. Else if `images` field exists → use it (multiple images)
3. Else → text-only mode

### 2. MultimodalJSONDataLoader

Loads multimodal data from JSON array files.

#### JSON Format

```json
[
  {"id": "1", "prompt": "Describe this", "image": "img1.jpg"},
  {"id": "2", "prompt": "What is this?", "image": "img2.png"},
  {"id": "3", "prompt": "Compare", "images": ["a.jpg", "b.png"]}
]
```

Configuration is identical to MultimodalJSONLDataLoader, except the input is a JSON array file.

## Image Handling

### Image Sources

Loaders support multiple image sources:

1. **File paths** (relative or absolute):
   ```json
   {"image": "photos/sample.jpg"}
   {"image": "/absolute/path/to/image.png"}
   ```

2. **Relative paths with base directory**:
   ```yaml
   loader:
     params:
       image_base_dir: /path/to/images
   ```
   Then in JSONL:
   ```json
   {"image": "subdir/sample.jpg"}  # Resolves to /path/to/images/subdir/sample.jpg
   ```

3. **URLs** (passed through without encoding):
   ```json
   {"image": "https://example.com/image.jpg"}
   ```

4. **Already base64-encoded data**:
   ```json
   {"image": "data:image/jpeg;base64,/9j/4AAQSkZJRg..."}
   ```

### Image Encoding

By default, loaders automatically encode image files to base64 with data URI scheme:
- JPEG: `data:image/jpeg;base64,...`
- PNG: `data:image/png;base64,...`
- GIF: `data:image/gif;base64,...`
- WebP: `data:image/webp;base64,...`
- BMP: `data:image/bmp;base64,...`

To disable automatic encoding (for URLs or pre-encoded data):
```yaml
loader:
  params:
    encode_images: false
```

## OpenAI Vision API Format

The framework uses OpenAI's vision API format for messages:

### Single Image

```json
{
  "role": "user",
  "content": [
    {"type": "text", "text": "Describe this image"},
    {"type": "image_url", "image_url": {"url": "data:image/jpeg;base64,..."}}
  ]
}
```

### Multiple Images

```json
{
  "role": "user",
  "content": [
    {"type": "text", "text": "Compare these images"},
    {"type": "image_url", "image_url": {"url": "data:image/jpeg;base64,..."}},
    {"type": "image_url", "image_url": {"url": "data:image/png;base64,..."}}
  ]
}
```

This format is automatically generated by the multimodal loaders.

## Configuration Example

Complete example for vision model inference:

```yaml
# configs/multimodal_config.yaml
loader:
  class: MultimodalJSONLDataLoader
  params:
    file_path: data/vision_prompts.jsonl
    image_base_dir: data/images
    encode_images: true

saver:
  class: JSONLResultSaver
  params:
    output_path: results/vision_results.jsonl

runner:
  model_name: llava-hf/llava-1.5-7b-hf
  temperature: 0.7
  max_tokens: 512
  max_concurrency: 5
  request_timeout: 180  # Vision models may need more time
  adapter_class: OpenAIAdapter

logging:
  level: INFO
  file: logs/vision_inference.log
```

## Running Multimodal Inference

```bash
python -m src.cli --config configs/multimodal_config.yaml
```

## Vision Model Requirements

Your vLLM server must be running a vision-capable model. Popular options:

- **LLaVA**: `llava-hf/llava-1.5-7b-hf`
- **LLaVA-NeXT**: `llava-hf/llava-v1.6-34b-hf`
- **Pixtral**: `pixtral-12b`
- **Other VLMs**: Any model with vision support via OpenAI API

Make sure your vLLM server is started with the correct model and supports the vision API endpoint.

## Creating Custom Multimodal Loaders

To create a custom multimodal loader, inherit from `MultimodalDataLoader`:

```python
from src.loaders.multimodal_base import MultimodalDataLoader, MultimodalLoadResult

class MyCustomLoader(MultimodalDataLoader):
    def _initialize(self):
        super()._initialize()
        # Your initialization code
        self.data = [...]

    def load(self):
        for item in self.data:
            yield self._create_multimodal_result(
                text=item["prompt"],
                images=item.get("images", []),
                request_id=item["id"],
                additional_data={"metadata": item.get("metadata")}
            )
```

Then register it in your config:
```yaml
loader:
  class: MyCustomLoader
  params: {...}
```

## Troubleshooting

### Issue: "Image file not found"

**Solution**: Check that:
1. Image paths are correct
2. `image_base_dir` is set if using relative paths
3. Image files exist and are readable

### Issue: "Unsupported image format"

**Solution**: The framework supports JPEG, PNG, GIF, WebP, and BMP. Convert your images to one of these formats.

### Issue: Model returns errors about vision input

**Solution**: Ensure:
1. Your vLLM server is running a vision-capable model
2. The model supports the OpenAI vision API format
3. Images are properly encoded to base64 (or `encode_images: false` for URLs)

### Issue: Slow processing

**Solution**: Vision models typically need more time:
- Increase `request_timeout` (default: 120s)
- Reduce `max_concurrency` to avoid overloading the server
- Use smaller images if possible

## Best Practices

1. **Image Size**: Use reasonably sized images (< 5MB recommended)
2. **Encoding Costs**: Base64 encoding increases size by ~33%. Consider URLs for large images.
3. **Concurrent Requests**: Vision models are resource-intensive. Use lower concurrency.
4. **Timeout**: Vision requests take longer. Set `request_timeout` to 180s or more.
5. **Validation**: Test with a few samples before processing large datasets.

## Performance Considerations

- **Image Encoding**: Automatic base64 encoding adds overhead during loading
- **Network Transfer**: Base64 images are larger than binary files
- **Memory Usage**: Each worker holds encoded images in memory
- **Server Load**: Vision models require more GPU memory and compute

For large-scale vision inference:
- Use `encode_images: false` with hosted image URLs if possible
- Process in smaller batches
- Monitor server GPU memory usage
- Consider reducing image resolution for faster processing
